# Reds Social League — AI maintainer guide

Read this before changing anything. The README covers what the plugin
does; this file covers how to work on it safely.

## What this is

A WordPress plugin for MURVC's social volleyball league (Reds Social
League) on the club's members site. The full design — divisions,
ratings, weekly fixtures, payments, refs, finals, season calendar — is in
the club's design doc; build to it, phase by phase:

1. **Registration and payments** — players, teams, invites, free agents,
   sub list, team balances. Fixtures still made by hand.
2. **Results and ladders** — refs claim courts and enter scores, live
   ladder and fixtures pages, ref pay report.
3. **Ratings and fixturing** — Bradley-Terry ratings (shadowed first),
   rating-based weekly pairing, double-headers, finals.

It sits beside the club's other plugin, **MURVC Club Manager**
(`team-oversight-migration`), which runs memberships, VVL trials and VVL
fees. Keep the two separate: this plugin may *read* from the Club Manager
(membership status, activity log) through a small, checked API
(`class_exists` first, degrade gracefully), never write to its tables.

## This repo will be PUBLIC — privacy rules from day one

It's private now, but goes public when it's installed on the site (the
free Git Updater plugin needs a public repo). So write everything as if
it were public already:

- No member data: no dumps, CSVs, exports, screenshots of admin pages, or
  fixtures with real names, emails, phone numbers or DOBs. Test data is
  generated (`@example.test`) and deleted.
- No credentials, API keys, security-plugin details, or hosting specifics
  (server paths, DB names/prefixes, hosts) in code, docs or commits.
- Describe data issues by shape, never with real examples.

## Public pages show teams, not people

Public pages (team list, team pages, later fixtures/results/ladder) show
team names, badges, divisions and results — never player names. Rosters
and anything personal are for the people involved (the team's members,
captains, admins). Under-18s play in the league.

The season preview card (0.18.0, `RSL_Public::season_preview()`) is the same
HTML for every viewer, since a page cache may serve it to anyone: it counts
active teams by division and never shows a team name, a person, or anything
about applications still waiting.

Two more privacy rules from registration: **a captain sees teammates'
names and ✓ cleared / ✗ needs rego only — never why** (membership vs paid
rego); and **joining by email needs the player to accept** (until then the
captain sees only the email they typed — and gets the same answer whether
or not that email is registered). Being on a team never needs payment;
being cleared is what's needed before a first game.

Free agents (0.12.0): **captains browsing the list see first name, level,
positions and "+N friends" only** (built only by
`RSL_Free_Agents::browse_for_captain()`; a test pins the keys). No free
text from players anywhere. Under-18s are left out of the captain's browse
list (the `under18_in_pool` setting is off by default). Since 0.13.0 nobody
is asked: under 18 comes from the date of birth on the account
(`RSL_Players::is_under18()`, judged on the earlier of today and the
season's first night; no date of birth counts as under 18), plus an
admin-only *Treat as under 18* tick (the `under18` column, written only by
`RSL_Free_Agents::admin_update()`). Every check goes through
`RSL_Free_Agents::under18_for()`, never `$row->under18` alone. The league
reads the date of birth and never stores it, and an age is never shown to
a captain. An under-18 can still ask a team themselves;
that captain then sees their request card (first name, level, positions),
and an accepted request swaps emails, as placement does (spec O11 — the
committee's call). Friend groups use shareable codes,
never email lookups. Contact details move only by email, only between a
player and their own captain, only when joining through the league. Admin-
only: est_level, band, band_override, admin_note, placement reasons.

**One team per person per season** holds on every route because
`RSL_Teams::add_member()` is the only way onto a roster: it takes a
per-person `GET_LOCK` and, for capped adds (active team, not admin), the
team's lock first (`RSL_Teams::team_lock_name()`; `RSL_Free_Agents::add_unit()`
holds it across a whole group), so two people can't push a team over the
maximum; it enforces the roster maximum (except `admin`), and fires
`rsl_member_added`. Don't insert into `rsl_team_members` anywhere else.
Locks are always taken team first, then person.

It returns options, one for each top count from the line (the k-th lowest) up: teams more than `sit_level` below it must sit out, teams up to it may; `pair_division()` takes the option whose best matching costs least. The guard: a team that sat out its last night doesn't sit out again while a team in its division that has never sat out plays (an option keeps every such team in, or puts every never-sat-out team out too; when none is left, the never-sat-out teams' counts are taken as just below the lowest of those teams and they go first, `first`). So the count measures sit-outs per night available, and a team available every night has a whole count. `context()` leaves out an earlier night that was never published and has started (called off): its draft gives no sit-outs, shares, meetings, home games or doubles; a draft for a night still to come counts. Known limits (README 0.18.2): the draw can't tell other reasons afterwards, so a team taken out of a night by hand counts as having sat out, and whether a night was drawn before a team joined goes by its earliest game (a game added by hand later doesn't change it); a moved team is judged by its old division between its last game there and its first in the new, and counts toward the old division's share that night, and a team moved before its first game is judged by its division now on the nights before it joined; a share is the night's average; late joiners and teams back from nights away still sit out a little less than their share (simulated: 0.13 and 0.04 of a night a season on average), partly the cost among level teams (its rematch costs; not the rating uncertainty) and partly the rotation (a count with a fraction puts a team at the same place in it every season, and where the season ends decides whether its next sit-out comes), and a coin toss among level teams doesn't cure it and costs closeness; a double-header team's extra rematches make it a little more likely to lose a tie. Spare-slot double-headers are unchanged, never make up for a sit-out, and their checks judge games without the link. ## Rules

- **PHP 7.4 and 8.x.** The site is on 7.4 now and moving to 8.x. No PHP 8-only syntax (no `str_contains`, `match`, nullsafe `?->`, named args, union types). Lint on both before every push.
- **Tables are `{$wpdb->prefix}rsl_*`** via `RSL_Database::table()`; never hardcode a prefix. Changes are additive (never rename/drop; add and backfill).
- **Anything that names an account is listed for merges.** A new table or column holding an account id goes into `RSL_Merge::columns()` in the same commit; a new option entry (or any other place outside the tables) holding one goes into `RSL_Merge::uses()`. `dev/tests/test-merge.php` reads the schema and fails on a `user_id` / `*_by` column, or any other `bigint` column not on its list of ids that aren't accounts, that isn't listed; nothing checks the places outside the tables. The wording of a refusal never weakens it: every row naming the account counts.
- **Team images are fetched by the avatar job only** (0.23.0): never call DiceBear (or any outside image) while drawing a page, never work out a level for a badge (it draws the stored `avatar_stage`), and never put an outside address in a page, with the one exception the club agreed (7 Nov 2026): the robot chooser's previews (`RSL_Avatars::chooser()`), straight from `api.dicebear.com`, only for the captain or league admin using that box, with no referrer and never the team's name. A badge with missing files draws the initials and queues the team (`RSL_Avatars::missing()`). Everything fetched goes through `RSL_Avatars::clean()` before it's saved. Every part and colour of a robot is pinned from its seed by `RSL_Avatars::picks()`: never change the hash, a list or its order (test-avatars pins the example seed), as that reshuffles every team's robot; a new stage only ever adds.
- **People are WordPress users, keyed by `user_id`.** Emails are for display only.
- **Every admin action**: nonce + `RSL_Access::can()` (the capability `RSL_Access::CAP`, `rsl_manage_league`: Social League admins hold it through their role, administrators through `RSL_Access::grant_admins()`), processed in admin-post, then redirect with a notice; a new Social League screen's menu capability is `RSL_Access::CAP`. Front-end actions check that the user may act on *that* team, server-side: its captain (or a member, where members may) or `RSL_Access::can($user_id)`. Never check `manage_options` for league work (0.22.0): only the League admins screen and its actions (`manage_options` and `promote_users`), the grant, the Dashboard rule and `may_choose_products()` in `RSL_Access` read it, and `dev/tests/test-league-admin.php` fails on any other. Choosing a shop product the league sells (top-up, rego) is not league work: it asks `RSL_Access::may_choose_products()`.
- **Always `wp_unslash()` typed text from `$_POST`/`$_GET` before sanitising** — WordPress adds magic-quote slashes to all input.
- **Data rules live in the data classes** (`RSL_Teams` …), not in admin or page code, so tests can call them directly.
- **Slugs are permanent**: renaming a team never changes its public URL.
- **Rego cover on a date is the rows' dates; a season rego also counts for its season.** `rego_valid_until()`, `clearance()` and `count_current()` use `start_date` / `end_date` only, whatever the kind; a row's end is fixed when it's granted (`granted_end`) and never rewritten from the season's dates. A season row also counts for its own season while that season runs (`RSL_Rego::row_counts()` / `season_row()`, used by `clearance_for()` and `season_covered()`), so moving a season's nights never makes a paid player pay again or shows them ✗. Refunds, cancellations and removals (`revoke()`) end a row from today, and always cut a season row short (its end moved back below `granted_end`, even when its own dates are already over); a row cut short never counts for its season, whatever the season's dates do later. An order paid again puts `granted_end` back.
- **Public pages and anything a player sees use the ladder rating** (`RSL_Ratings::compute(..., 'ladder')`); the seeded `'fixtures'` rating is only for making fixtures, placing free agents and the admin set chances. **The `'ladder'` kind must never read a level** — no `est_level`, no seed, for any team at any game count; its only link to levels is the season's frozen start (`start_for()`), one number for every team. Any new public number (a rating, change, chance, tier, place, tag) must come from `compute(..., 'ladder')`. A new reader of ratings names its kind; `dev/tests/test-fixtures.php` checks that editing levels after night one leaves every ladder rating, tier and place exactly as it was, teams under 5 games included.
- **Clearance for a season goes through `RSL_Rego::clearance_for()`.** Anything that shows whether someone can play in a season (league page, rosters, emails) uses it, so a season rego paid ahead counts; `clearance()` alone answers for one date. It agrees with `season_covered()` (what the shop refuses as already covered): someone the shop won't sell a season to is never shown as needing to pay for it.
- **Every league email goes through `RSL_Mail`**: `queue()` for anything that can go to many people, `send_now()` for one time-critical email; never `wp_mail()` directly (it would skip the club look). Write the body as plain text: paragraphs at blank lines, an address the reader should click alone on its line (after a short `Label:` line to name the button), an address to share with `join=` (it stays visible).
- **A season a player picks goes through `RSL_Seasons::pick_open()`** (the seasons open for sign-up; with none open it refuses with `closed_words()`, never falling back to a finished season). `RSL_Teams::apply()` and `RSL_Free_Agents::join()` accept any valid season for admin screens, scripts and tests; only admin screens offer `choices()`.
- **My team is a custom menu link ending `#rsl-my-team`** (0.20.0): `RSL_Portal::my_team_items()` points it at the viewer's team page (`my_team_url()`) and removes it for anyone on no team, logged out included, so a cached page never shows it.
- **The league page's menu item is relabelled for logged-in viewers only.** A logged-out visitor's item is static (and may be served from a page cache), and an item marked for logged-out visitors (`_nav_menu_role` `out`) is never touched.
- **Rego notes are cut by bytes on a character boundary, the newest reason kept whole** (`RSL_Rego::note_fit()` / `note_add()`). `restore_cancelled()` reads the last `— ` part, so never write a note any other way. Team balance (ledger) notes are cut the same way (`RSL_Rego::note_fit_to()`), never with `substr()`.
- **The league never names a sender.** The From line comes from the Club Manager's sender setting (club look) or the site's default (plain); never add a From header or a `wp_mail_from` / `wp_mail_from_name` filter.
- **Commit messages must not contain double quotes** (PowerShell argument passing on the maintainer's machine mangles them).

## Development workflow

Build and test on the **local Docker copy** of the site (containers
`murvc_wp`, `murvc_cli`, `murvc_db`; site at `localhost:8080`). The plugin
isn't deployed anywhere until Deployer / Git Updater is pointed at this
repo, so nothing reaches the live site by accident.

1. Edit code here.
2. Lint on both PHP versions:
   `docker run --rm -v <repo>:/code php:7.4-cli php -l /code/<file>.php` and the same with `php:8.3-cli`.
3. Copy to local: `docker cp <repo>/. murvc_wp:/var/www/html/wp-content/plugins/reds-social-league/` (and to `murvc_cli` for WP-CLI).
4. Run the tests, one file at a time (they share the database): `docker exec -e RSL_DEV=1 murvc_cli wp eval-file wp-content/plugins/reds-social-league/dev/tests/test-teams.php --path=/var/www/html`. Each prints OK/FAIL lines and ends with ALL PASSED or a count. (The local copy reports itself as `production`, hence `RSL_DEV=1`.)
5. Look at it: `wp eval-file .../dev/fake-season.php` fills the current season, then `.../dev/fake-signup.php` adds next season's sign-ups; `... reset` removes each.
6. Bump the version (header + `RSL_VERSION`), update the README if behaviour changed, commit, push.
